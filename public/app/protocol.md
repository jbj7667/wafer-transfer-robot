# 로봇 ↔ 스마트폰 BLE 통신 프로토콜

## 1. 물리 계층

| 항목 | 값 |
|---|---|
| 로봇 MCU | Arduino Mega 2560, HM-10을 `Serial3`(TX3=14, RX3=15)에 연결, 9600 bps 8N1 |
| BLE 서비스 UUID | `0000FFE0-0000-1000-8000-00805F9B34FB` (짧게 `FFE0`) |
| 특성(Characteristic) UUID | `0000FFE1-0000-1000-8000-00805F9B34FB` (짧게 `FFE1`) |
| 특성 속성 | Notify(로봇→앱) + Write / Write Without Response(앱→로봇) |
| 인코딩 | ASCII, 한 줄 = 한 메시지, 종단 문자 `\n` (0x0A). `\r`은 있어도 무시 |

HM-10 기본 UUID 근거(검색 확인):
- 서비스 0xFFE0, 특성 1 = 0xFFE1 이며 Read/Notify/Write Without Response 속성이라는 자료와, Read/Write/Notify 로 적은 자료가 있어 속성 표기는 자료마다 조금 다르다. 서비스·특성 UUID 값 자체는 일치한다.
  - HM-10 UUID 설정 문서: <https://www.scribd.com/document/507909104/HowToConfigUUID>
  - Martyn Currey, HM-10 특성 추가: <https://www.martyncurrey.com/?p=11416>
  - MIT App Inventor 커뮤니티 HM-10 스레드(FFE0/FFE1 사용 예): <https://community.appinventor.mit.edu/t/hm-10-ble-arduino-uno-notify-bluetooth-at-ibeacon-arrhythmia/12621>
- 대회 지급 모듈이 클론(MLT-BT05, AT-09 등)이면 같은 FFE0/FFE1 이지만 쓰기 속성이 다를 수 있으므로 앱의 쓰기 방식 2종(README 5절)을 모두 시험한다.
- 주의: BLE 한 번의 알림(notification)은 기본 MTU에서 **최대 20바이트**이다. 한 줄이 20바이트를 넘거나, 여러 줄이 한 알림에 합쳐질 수 있으므로 앱은 반드시 버퍼에 이어 붙여 `\n` 기준으로 줄을 재조립한다(3절).
- 이 프로토콜의 한 줄은 최대 `V,10.00,10.00\n` = 15바이트로 20바이트 이내지만, 로봇은 `Serial3.print` 로 보내므로 HM-10이 시간 간격에 따라 임의 지점에서 쪼갤 수 있다.

## 2. 메시지

### 2.1 로봇 → 앱

| 메시지 | 형식 | 주기/시점 | 예 |
|---|---|---|---|
| 전압 | `V,<제어전압>,<모터전압>\n` | 500 ms 마다 | `V,8.97,7.41\n` |
| 상태 | `S,<STATE>\n` | 상태가 바뀔 때 (그리고 연결 직후 현재 상태를 한 번 더 보내 주면 좋음) | `S,IDLE\n` |
| 핑 응답 | `K\n` | `P` 수신 시 | `K\n` |

- 전압 단위는 V(볼트), 소수점 `.` 사용, 소수 2자리 권장, 음수·지수 표기 없음.
- 첫 번째 값 = 제어 9 V 팩, 두 번째 값 = 모터 7.2 V 팩.
- `STATE` 는 다음 6개 중 하나(대문자):

| STATE | 의미 | 앱 표시 색 | START 가능 |
|---|---|---|---|
| `BOOT` | 부팅 중 | 회색 | 아니오 |
| `HOMING` | 원점(홈) 복귀 중 | 주황 | 아니오 |
| `IDLE` | 대기, 출발 가능 | 초록 | **예** |
| `RUN` | 주행 중 | 파랑 | 아니오 |
| `ARRIVED` | 도착 완료 | 보라 | 아니오 |
| `FAULT` | 오류 | 빨강 | 아니오 |

알 수 없는 STATE 문자열은 무시하지 말고 그대로 표시하되(회색) START는 비활성으로 둔다.

### 2.2 앱 → 로봇

| 명령 | 의미 | 로봇 동작 |
|---|---|---|
| `S` | 출발 | IDLE 일 때만 RUN 으로 전환, 아니면 무시 |
| `H` | 재홈 | IDLE 일 때만 HOMING 으로 전환, 아니면 무시 |
| `P` | 핑 | 즉시 `K\n` 응답 |

- 앱은 `S\n`, `H\n`, `P\n` 처럼 **개행을 붙여** 보낸다. 로봇 쪽은 개행이 없어도, `\r\n` 이어도 한 글자 명령을 처리하도록 구현한다(test_echo.ino 가 그렇게 동작).
- 명령은 응답(ACK)이 없다(핑 제외). 성공 여부는 이어서 오는 `S,<STATE>` 로 확인한다. 앱은 `S` 를 보낸 뒤 2초 안에 `S,RUN` 이 오지 않으면 "출발 응답 없음" 을 표시한다.

## 3. 파싱 규칙 (앱 수신 측)

1. 알림이 올 때마다 받은 문자열을 전역 버퍼 `rxBuf` 뒤에 이어 붙인다.
2. `\r` 은 모두 제거한다.
3. `rxBuf` 를 `\n` 으로 분리한다. 결과 리스트의 **마지막 항목은 아직 끝나지 않은 조각**이므로 `rxBuf` 에 되돌려 두고, 나머지 항목만 완성된 한 줄로 처리한다. (알림이 `"V,8.9"` + `"7,7.41\n"` 으로 쪼개져도, `"S,IDLE\nV,8.97,7.41\n"` 으로 합쳐져도 정상 처리된다.)
4. 한 줄에서 앞뒤 공백을 제거하고, 빈 줄은 버린다.
5. 첫 글자로 분기한다.
   - `V,` 로 시작: `,` 로 분리해 항목이 3개이고 2·3번째가 숫자이면 전압 갱신. 아니면 버린다.
   - `S,` 로 시작: `,` 뒤 문자열을 STATE 로 사용(대문자 변환).
   - 정확히 `K`: 핑 응답. 지연 = 현재시각 − 핑 송신시각.
   - 그 외: 무시(디버그 라벨에만 표시).
6. 버퍼 보호: `rxBuf` 길이가 200자를 넘으면 쓰레기 데이터로 보고 비운다.
7. 연결이 끊기거나 새로 연결되면 `rxBuf` 를 비운다(이전 연결의 반쪽 줄이 섞이지 않도록).
8. 로봇의 `V` 가 2초 이상 오지 않으면 앱은 "수신 끊김" 으로 표시하고 START 를 비활성화한다.

### 파싱 예 (같은 데이터가 어떻게 와도 결과가 같아야 한다)

| 알림 순서 | 처리 결과 |
|---|---|
| `V,8.97,7.41\n` | 한 번에 V 1건 |
| `V,8.` → `97,7.41\n` | 첫 알림 후 버퍼=`V,8.`, 둘째 후 V 1건 |
| `S,IDLE\nV,8.97,7.41\n` | S 1건 + V 1건 |
| `V,8.97,7.41\nS,RU` → `N\n` | V 1건, 이어서 S,RUN 1건 |
| `\nV,8.97` → `,7.41\n` | 빈 줄 버림, V 1건 |

## 4. 시퀀스 예

```
앱                         로봇
 | --- (BLE 연결, FFE1 notify 등록) -->
 | <---------------- S,IDLE\n
 | <---------------- V,8.97,7.41\n   (500 ms마다 반복)
 | ---- P\n -------------------->
 | <---------------- K\n             (지연 측정)
 | ---- S\n -------------------->
 | <---------------- S,RUN\n
 | <---------------- V,8.95,7.05\n
 | <---------------- S,ARRIVED\n
 | ---- H\n -------------------->   (IDLE 이 아니면 무시됨)
```

## 5. 로봇 펌웨어 구현 시 주의

- `V` 와 `S` 송신은 `Serial3.print(...); Serial3.print('\n');` 로 한 줄씩. 주행 중 `Serial3` 쓰기가 제어 루프를 막지 않도록 `Serial3.availableForWrite()` 로 확인하거나, 줄 길이가 짧으므로(최대 15바이트) 500 ms 주기에서는 9600 bps 에서 약 16 ms 이므로 문제 없다(블로킹이 아니라 송신 링버퍼에 들어감).
- 수신은 `while (Serial3.available()) { char c = Serial3.read(); ... }` 로 글자 단위 처리, `\r` `\n` 무시.
- `S` 는 IDLE 에서만 받는다. 이미 RUN 이면 무시해서 중복 출발을 막는다.

## 추가: 자가 점검 메시지 (펌웨어 SELFTEST 상태)

| 방향 | 형식 | 예 | 앱 처리 |
|---|---|---|---|
| 로봇 → 앱 | `T,<항목>,<결과>` 항목 = `IR`·`LINE`·`VBAT`, 결과 = `OK`·`WARN`·`FAIL` | `T,IR,OK` | 상태 라벨 아래 작은 라벨에 항목별로 표시(OK 초록, WARN 주황, FAIL 빨강). 모르는 첫 글자의 줄은 무시하는 기존 규칙과 호환 |

상태 순서는 `HOMING → SELFTEST → IDLE`이다. START 버튼 활성 조건(연결됨 AND 상태=IDLE)은 바뀌지 않는다.
